# Coding Rules

## Общие

- Пиши простой, читаемый код.
- Предпочитай явные решения хитрым.
- Не добавляй абстракции «на будущее», если они не нужны сейчас.
- Следуй стилю и соглашениям, уже принятым в проекте (`PROJECT.md`).

## Структура

- Держи файлы небольшими и по одной ответственности.
- Не раздувай один файл на тысячи строк без необходимости.
- Имена файлов и папок — понятные, на английском.

## Зависимости

- Не добавляй новые зависимости без необходимости.
- Если добавляешь — отрази в `PROJECT.md`.
- Предпочитай стандартную библиотеку и уже используемые пакеты.

## Тесты и проверка

- После изменений убедись, что проект собирается / запускается.
- Если в проекте есть тесты — запускай их.
- Не оставляй заведомо сломанное состояние.

## Комментарии

- Комментируй неочевидные места.
- Не пиши комментарии, которые просто повторяют код.
- TODO/FIXME — только если есть конкретный следующий шаг.
